1) Resete completamente o banco da aplicação:

    docker start vertex_postgres
    npx prisma migrate reset
    npx prisma generate
    npm run dev
    Veja rodando em http://localhost:3000
    Em caso de erro use: npx prisma db push --force-reset

==========================================================================================================================
2) Abra a plataforma em http://localhost:3000/

==========================================================================================================================
3) Vá para configurações (settings). Temos que fazer o pareamento com o dispositivo móvel (no caso aqui simulado)
   Na tela Settings clique em "iniciar pareamento" e depois "Copiar Payload Comppleto JSON"
   Execute o script abaixo substituindo PAYLOAD pelo payload copiado da plataforma.

    node lib/complete-pairing.js 'PAYLOAD'

    O script vai rodar e concluir de modo parecido com isto:

    👉 Agora observe a tela da plataforma web (http://localhost:3000/settings)!
       Ela atualizará automaticamente para o estado PAREADO.

==========================================================================================================================
4) Na plataforma, crie um esquema e emita uma credencial. Na listagem de credenciais emitidas ela vai aparecer como "PENDENTE",
   ou seja, ela ainda não foi assinada pelo aplicativo MOBILE.

7) Se quiser testar a validação via Hash mais tarde na tela pública, você pode extrair o SHA-256 exato deste PDF em claro agora. 

    node lib/get-pdf-hash.js lib/credential_XXXXXXXX.pdf 

    Guarde o hash retornado para colar na aba “PDF Hash” da página de Verificação.

8) Para fazer o downlod pelo app use:

    node lib/simulate-mobile-download.js

    Este script simula o App fazendo a chamada API de download do arquivo .enc, abrindo a
    mobile_wallet.db e realizando a decapsulação (ML-KEM + AES-GCM) para gerar o PDF em claro localmente.

    Uma outra maneiar é baixar o PDF pela plataforma e depois decifrar com o app:

    node lib/decrypt-local-pdf.js lib/credential_cmseq2azc0005sxxkfjsigi88.pdf.enc

    A saída é a credencial decifrada também.
    
    =================================================

    🔓 Decifrando PDF com AES-256-GCM...
    ✅ Sucesso! Arquivo decifrado salvo na pasta atual como: credential_cmseq2azc0005sxxkfjsigi88.pdf_decifrado.pdf

==========================================================================================================================
9) Validação:

    Acesse localhost:3000/verify:

    Pode validar pelo hash do PDF neste caso você pode calculá-lo facilmente conforme mostramos no passo 7.
    Na aba PDF hash colo que hash obtido pelo passo 7 (ou copie o hash direto da plataforma)
    Você verá que a credencial é válida.

    Para validar de forma criptográfica você deve fazer o upload do PDF decifrado na aba "Upload de PDF"
    Aqui também você valida facilmente o PDF com a ressalva:

    A verificação por PDF expõe os dados momentaneamente para validação criptográfica (SSI), 
    mas a plataforma não armazena nenhuma informação e descarta o arquivo imediatamente após o processamento.

    No caso de verificar o PDF em claro você expõe o PDF da mesma forma que faria na plataforma GOV.BR
    No caso de verificação pelo HASH a plataforma apenas faz uma comparação de hashes e portanto não
    expomos os dados a plataforma.
