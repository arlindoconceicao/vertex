# SSI-PQ Interoperability Test Vectors

This directory stores cross-platform vectors for the Node, WASM, Android and
iOS implementations.

## Layout

- `node/manifest.json`: vectors generated by the Node.js addon.
- `node/files/`: binary artifacts referenced by the Node manifest.
- Future platform generators should write to `android/manifest.json` and
  `ios/manifest.json` with the same schema shape.

## Vector Contract

Each vector entry must include:

- `input`: data needed by another platform to verify or replay the operation.
- `expected`: expected values, verification status or extracted metadata.
- `files`: binary artifacts with `path`, `size`, `sha3_256_base64url` and
  `sha3_256_hex`.
- `generatedBy`: generator platform, package version and runtime.
- `verifyWith`: platforms that must verify the vector.

Private keys may appear only in primitive test vectors where they are required
to verify decapsulation or a low-level test operation. Product-level wallet,
DID, credential and PDF vectors must not export wallet private keys.

## Current Coverage

The Node generator creates vectors for:

- canonical JSON and canonical JSON hash;
- SHA3-256 and base64url helpers;
- ML-DSA signing and verification;
- ML-KEM encapsulation and decapsulation;
- AES-256-GCM encryption and decryption;
- valid and tampered DID Documents;
- valid and tampered signed credentials;
- valid and tampered credential PDFs;
- valid and tampered generic signed PDFs;
- wallet flow with DID, credential, credential PDF, generic PDF and ML-KEM
  decapsulation without exporting wallet private keys.

## Commands

Generate Node vectors:

```sh
npm run vectors:generate:node
```

Verify Node vectors:

```sh
npm run vectors:verify:node
```

Acceptance for phase 6 is complete when each platform can verify manifests
generated by the other platforms:

- Node -> Android/iOS/WASM;
- Android -> Node/WASM/iOS;
- iOS -> Node/WASM/Android.
